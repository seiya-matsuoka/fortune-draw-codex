# 設計

## 1. 全体構成

外部依存を持たない静的 Web アプリとして構成する。

```text
fortune-draw-codex/
├─ AGENTS.md
├─ index.html
├─ style.css
├─ script.js
└─ docs/
   ├─ 01-requirements.md
   ├─ 02-design.md
   └─ 03-development-plan.md
```

`docs/03-development-plan.md` は、Codex の Plan で実装計画を確定した後に作成する。

## 2. ファイル責務

### `index.html`

- アプリの画面構造を定義する。
- タイトル、簡単な説明、おみくじを引くボタン、結果表示領域を持つ。
- CSS と JavaScript を読み込む。
- 操作性とアクセシビリティのため、適切な HTML 要素を使用する。

### `style.css`

- 1 画面のおみくじアプリとして必要な見た目を定義する。
- 中央寄せを基本とした、シンプルで読みやすいレイアウトとする。
- PC とスマートフォンの一般的な画面幅に対応する。
- 複雑な装飾、外部フォント、外部画像は使用しない。

### `script.js`

- おみくじ候補を定義する。
- ボタン操作を受け取り、候補からランダムに 1 件選択する。
- 選択結果を結果表示領域へ反映する。
- DOM 操作と抽選処理を必要以上に分割せず、小規模アプリとして読みやすい構成を維持する。

## 3. 画面構成

1 画面に次の要素を配置する。

```text
タイトル
簡単な説明

[ おみくじを引く ]

結果
運勢
メッセージ
```

初期状態では、結果領域に「まだおみくじを引いていない」ことが分かる表示を行う。

## 4. おみくじデータ

JavaScript 内に、運勢とメッセージを組み合わせたデータを保持する。

概念例:

```text
大吉 + メッセージ
中吉 + メッセージ
小吉 + メッセージ
吉   + メッセージ
末吉 + メッセージ
凶   + メッセージ
```

メッセージは短く、各運勢の違いが分かる程度とする。
具体的な文言は実装時に決定してよい。

## 5. 抽選処理

1. ボタンのクリックを受け取る。
2. おみくじ候補数を基にランダムな index を生成する。
3. 対応する運勢とメッセージを取得する。
4. 結果表示領域を更新する。

特別な重み付けは行わず、各候補を同じ確率で選択する。

## 6. UI 方針

- 特定のデザインテーマを細かく固定せず、Codex が要件の範囲内でシンプルに実装してよい。
- 余白、文字サイズ、ボタンの視認性を確保する。
- 色数を増やしすぎず、結果を読み取りやすくする。
- 過度なアニメーションや演出は追加しない。
- JavaScript が動作しない場合でも、画面の基本構造が理解できる HTML とする。

## 7. アクセシビリティ

- おみくじ操作には標準の `button` 要素を使用する。
- 結果表示領域は、更新内容を支援技術が認識できる構成とする。
- キーボード操作時にフォーカス位置が分かる状態を維持する。
- 文字と背景の視認性を確保する。

## 8. 実装計画

具体的な実装工程は本設計では固定しない。

`AGENTS.md`、`docs/01-requirements.md`、本ファイルを Codex が確認したうえで Plan を作成し、ユーザーと内容を確認してから `docs/03-development-plan.md` として確定する。
